# 课择 CourseGrid · 选课冲突规划器

> 把教务系统里想选的课全录进来，它替你算出**不冲突、学分达标、且最符合你偏好**的那一版课表。

**在线地址**：https://eoiec.github.io/coursegrid/

零依赖 · 零联网 · 单文件 · 纯前端（HTML + CSS + JS，无任何框架与 CDN）

---

## 它解决什么

每学期选课都是同一套困境：

- 必修课时间锁死，选修只能往缝里塞
- 想选的课互相撞车，只能手动一个个试
- 学分有下限有上限，选多了超标、选少了不够
- 选完之后才发现：周三上午一节、晚上一节，中间白等四小时

手工排列组合最多试十几种，而 16 门选修的可行子集有 65536 个。**CourseGrid 把这 65536 个组合全部搜索一遍，只花 3 毫秒。**

## 核心算法

### 问题建模

```
给定课程集合 S，每门课 c 有：
  credit(c)   学分
  slots(c)    占用的 (周几, 第几节) 区间集合
  want(c)     想选程度 1–5
  required(c) 是否必修

求子集 W ⊆ S，满足：
  ∀ c₁,c₂ ∈ W: slots(c₁) ∩ slots(c₂) = ∅      （时间不冲突）
  ∀ c ∈ S, required(c) ⟹ c ∈ W                 （必修必选）
  L ≤ Σ credit(c) ≤ U                          （学分落在区间）

最大化目标函数 f(W)
```

把课程看作图的顶点、冲突看作边，这就是**带权最大独立集 + 背包约束**——NP-hard。课程规模在几十门以内时，回溯配合剪枝能在毫秒级给出**精确最优解**（不是启发式近似）。

### 三条剪枝

| 剪枝 | 做法 |
|---|---|
| 学分上界 | 当前学分一旦超过上限 `U`，该分支立即终止 |
| 后缀和上界 | 按价值密度降序预处理后缀和 `suf[i]`；若 `当前价值 + suf[i] ≤ 已知第 K 名`，整块剪掉 |
| 冲突位图 | 用长度 96 的 `Uint8Array` 记录「周几·第几节」占用，冲突检测退化为 O(占用节数) 查表 |

**实测**：22 门课（6 必修 + 16 选修），搜索空间 2¹⁶ = 65536，实际只展开 **1154** 个节点、剪掉 **643** 个分支，耗时 **3 ms**。剪枝率 98.2%。

### Top-K 而不只是最优

数字上的最优解不一定是你想要的那一版。所以求解器在搜索过程中直接维护一个长度为 K 的有序表，一次遍历收集前 K 个**互不相同**的解（按课程组合指纹去重），得到「含 A 的最优」「不含 A 的最优」这样有层次的候选集。

### 三种优化策略

| 策略 | 目标函数 |
|---|---|
| 学分优先 | `学分 × 想选程度` |
| 懒觉优先 | `学分 × 想选程度 − 早八/晚课惩罚` |
| 轻松优先 | `学分 × 想选程度 − 每周课时惩罚` |

同一批候选课、同一套约束，三种策略给出三种不同的最优解——这正是「取舍」的量化。

### 三个 KPI

- **早八**：第 1 节（08:00）有课的天数。会拆成「必修造成」和「选修造成」，前者无法通过选课优化。
- **空窗**：把一天切成上午 / 下午 / 晚上三段，某段无课却被夹在两段有课的时段之间，记为 1 段空窗。午休和晚饭不算。
- **空闲日**：整周完全没课的天数。

## 功能

- **候选课程**：增删改查课程（名称 / 学分 / 必修 / 想选程度 / 教师 / 地点 / 多段上课时间），自动标出「与必修冲突、永远选不上」的课
- **方案求解**：一键回溯求解，输出 Top-5 方案，展示搜索节点数、剪枝数、耗时
- **周课表**：周历网格视图，深色块为必修、浅色块为选修，按课程自动配色
- **方案对比**：关键指标横向对比（最优方案各项基准 100%），并列出每个方案「仅此方案独有」的课程
- **算法说明**：完整问题建模、剪枝策略、KPI 定义
- **数据**：localStorage 持久化、多方案管理、JSON 导出 / 导入

## 已知边界

- 目标是**精确最优解**，因此候选选修课超过约 25 门时搜索会触及 60 万节点上限并提前停止（此时返回的是已找到的最优解，仍保证可行但不再保证全局最优）
- 不考虑跨校区通勤时间、教师评价、课程难度等主观因素
- 单学期静态规划，不做跨学期联动
